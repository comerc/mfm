# Техническое ревью сервиса nsfw-mod

## Общая информация
Сервис предназначен для модерации контента (изображения и видео) на предмет NSFW (Not Safe For Work) с использованием ML моделей (OpenNSFW2, ViT) через ONNX Runtime.

## Архитектура
Проект следует принципам Clean Architecture и разделен на слои:
- **Service Layer** (`internal/service`): Содержит бизнес-логику.
- **Repository Layer** (`internal/repo`): Отвечает за работу с данными и внешними системами (файловая система, ML модели).
- **Entry Point** (`cmd/server`): Инициализация и запуск HTTP сервера.

Соблюдаются правила, описанные в `.kilocode/rules/architecture.md`:
- Используются интерфейсы для инверсии зависимостей.
- Структуры и конструкторы следуют конвенциям (`New`, `Service`, `Repo`).

## Анализ компонентов

### 1. Entry Point (`cmd/server/main.go`)
- **Плюсы**:
  - Использование `godotenv` для конфигурации.
  - Структурированное логирование через `slog` + `zap`.
  - Graceful Shutdown.
  - Проверка свободного порта.
- **Минусы**:
  - **Критично**: В хендлере `/moderate` (строка 67) отсутствует вызов метода `moderationService.Moderate()`. Стоит `TODO` и заглушка `_ = moderationService`. Сервис возвращает 200 OK, но не выполняет работу.

### 2. Service Layer (`internal/service/moderation`)
- **Плюсы**:
  - Четкое разделение ответственности.
  - Параллельная обработка (в теории, через `modelRunners`, но в коде последовательный перебор раннеров).
  - Агрегация результатов (max score).
  - Хорошее покрытие юнит-тестами (`service_test.go`) с использованием моков.
- **Замечания**:
  - Логика объединения результатов: выполняется инференс всех фреймов для каждой модели последовательно.

### 3. Repository Layer (`internal/repo`)

#### `media_reader`
- **Плюсы**:
  - Поддержка изображений и видео.
  - Использование `ffmpeg` для извлечения кадров.
- **Минусы**:
  - **Жесткая зависимость**: `New()` паникует, если `ffmpeg` не найден.
  - **Ручная обработка изображений**: В `processImage` используется ручной ресайз (nearest neighbor) и конвертация в RGB. Это может быть медленно и давать низкое качество по сравнению с оптимизированными библиотеками (например, `disintegration/imaging` или `nfnt/resize`), хотя для ML моделей nearest neighbor часто достаточно.
  - **Тесты**: Отсутствует реализация теста для видео (`TestService_Read_Video_Success` - TODO).

#### `open_runner` / `vit_runner`
- **Плюсы**:
  - Использование `onnxruntime_go`.
  - Корректная предобработка данных (нормализация, mean/std) специфичная для каждой модели.
- **Минусы**:
  - **Panic в конструкторе**: `New()` паникует при отсутствии переменных окружения или файлов моделей. Это затрудняет тестирование и использование пакета как библиотеки. Лучше возвращать ошибку.

## Тестирование

- **Интеграционные тесты**: Есть тесты в `test/moderation_test.go`, проверяющие работу с реальными файлами и моделями.
- **Бенчмарки**: Присутствуют бенчмарки для оценки производительности.
- **Замечания**:
